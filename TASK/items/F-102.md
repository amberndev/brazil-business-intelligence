# F-102 — Docs quickstart curl examples omit the /api prefix → the documented URLs 404

## F-102 | categoria: funcional | severidade: média | status: aberto
- Tela: `https://brazil.ambern.dev/docs` quickstart code block (source `frontend/src/app/docs/page.tsx:135-145`) instructs: `curl https://brazil.ambern.dev/v1/company/12345678000195` and `.../v1/search?...`.
- Passos:
  1) `curl -s -o /dev/null -w "%{http_code}" https://brazil.ambern.dev/v1/health` → **404**.
  2) `curl ... https://brazil.ambern.dev/v1/company/11222333000181` → **404**.
  3) Working path: `curl ... https://brazil.ambern.dev/api/v1/health` → **200**.
- Esperado: the public quickstart shows a URL that actually works.
- Observado: Caddy only reverse-proxies `/api/*` to the backend (`deploy/Caddyfile.brazil.snippet`); everything else goes to Next.js. So `https://brazil.ambern.dev/v1/...` hits the frontend and 404s. The real base is `https://brazil.ambern.dev/api/v1/...`. The rendered "Base URL: http://localhost:8100/v1" line is also wrong (same root cause as F-101).
- Plain impact: A developer copy-pasting the documented curl commands gets 404 and concludes the API is down; the correct base URL is never shown anywhere on the site.
