# F-102 — Self-serve FREE key UI throws on success (response-envelope mismatch)

## F-102 | categoria: funcional | severidade: alta | status: aberto
- Tela: live https://brazil.ambern.dev/app/keys — Chrome console at click:
  `TypeError: Cannot read properties of undefined (reading 'key')` (chunk 1jzri-2quhnjz.js).
  Code: `frontend/src/lib/api.ts:120-121`.
- Passos:
  1) Go to /app/keys, enter an email in "Get a Free Key", click "Create free key".
  2) Backend POST `/v1/keys` returns **201** with body `{"key","plan":"FREE","requests_limit":50,"message"}` (FLAT — no `data` wrapper). Verified by curl.
  3) `createFreeApiKey` does `const json = (await res.json()) as ApiResponse<{...}>; return {..., key: json.data.key, ...}` — `json.data` is `undefined` → throws.
- Esperado: on 201, the created key is shown once ("Key created for …", copy/save buttons).
- Observado: uncaught TypeError; UI stays on the create form, no key shown, no error message. The key IS created server-side (so retrying the same email then hits F-102's sibling 409). Headline new feature is unusable via the UI.
- (resolvedor) Correção: <pendente> — either read the flat body (`json.key`) or make the backend wrap the 201 in `{data:{...}}` to match `ApiResponse`. Note `CreateKeyResponse`/`createFreeApiKey` also expect `plan`/`email`; backend returns `plan` + `requests_limit` (no `email`) — align both ends.
