# F-101 — Prod frontend ships dev fallback API base URL (http://localhost:8100); /docs broken, whole app breaks once a key is entered

## F-101 | categoria: funcional | severidade: alta | status: aberto
- Tela: browser network log on `https://brazil.ambern.dev/docs` → request `http://localhost:8100/openapi.json` (statusCode 503); console: 2× `Failed to fetch` from redoc.standalone.js; page text renders "Base URL: **http://localhost:8100**/v1" and Redoc panel "Something went wrong... Failed to fetch".
- Passos:
  1) Open `https://brazil.ambern.dev/docs` in a browser.
  2) Observe Redoc never loads; DevTools Network shows a request to `http://localhost:8100/openapi.json`.
  3) Cross-ref `frontend/src/lib/api.ts:14` and `frontend/src/app/docs/page.tsx:5` — `BASE_URL = process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:8100"`. `frontend/.env.example` sets `NEXT_PUBLIC_API_URL=http://localhost:8100`.
- Esperado: prod build compiled with `NEXT_PUBLIC_API_URL=https://brazil.ambern.dev/api` so the browser calls `https://brazil.ambern.dev/api/openapi.json` (verified working: `curl https://brazil.ambern.dev/api/openapi.json` → 200).
- Observado: `NEXT_PUBLIC_API_URL` was NOT baked into the production Next.js build (it's a build-time inlined `NEXT_PUBLIC_*` var); the client falls back to `http://localhost:8100`. From a visitor's browser that host is unreachable AND mixed-content-blocked on an HTTPS page. Same fallback governs every authenticated call in `api.ts` (`/v1/search`, `/v1/company/{cnpj}`, `/compliance`, `/shareholders`, `/v1/company/batch`, `/v1/market/overview`) and `fetchHealth`.
- Plain impact: The `/docs` API reference is blank/broken for every visitor, and the moment any real user saves an API key the Search, Company, and Keys pages will all try to reach `localhost` and fail — the product is unusable in production even though the backend itself is healthy. Backend is fine; this is a frontend build-env defect (rebuild frontend with the prod `NEXT_PUBLIC_API_URL`).
